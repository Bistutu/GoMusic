# Implementation and open-source references

GoMusic's current product scope is public playlists-to-text only. Some source notes below record earlier research into album, single-track, and ranklist routes; those resource types are no longer accepted by the public API. Playlist provider code is independently implemented in Go against observed public platform protocols; it does not run or depend on reference repositories or third-party wrapper services.

### Migu public playlists (observed 2026-11-16)

The official [Migu playlist page](https://music.migu.cn/v5/#/playlist?playlistId=231760782&playlistType=ordinary) displayed 195 ordered tracks. The public metadata interface at `https://app.c.nf.migu.cn/resource/playlist/v2.0?playlistId=231760782` returned the title and `musicNum=195`. The public song-list interface at `https://app.c.nf.migu.cn/MIGUM3.0/resource/playlist/song/v2.0?pageNo=1&pageSize=50&playlistId=231760782` returned 50 rows and `totalCount=195`; page 4 returned 45 rows, also with `totalCount=195`. The adapter reads only playlist metadata and song names/artist names, not playback or download fields. The visible page and direct API responses were checked in the browser; no credentials were used. These endpoints are observed public interfaces, not a published stability guarantee.

### Qianqian public playlists (observed 2026-11-16)

The official [Qianqian share page](https://music.91q.com/songlist/295893) exposed the same URL in its share dialog. Its signed `https://music.91q.com/v1/tracklist/info` API returned title `许嵩 | 美好如约而至`, `trackCount=13`, 13 ordered track rows and `haveMore=0`. A second public homepage playlist at `/songlist/309500` returned 45 rows and a matching total. GoMusic reads only the metadata fields needed for text export; the API response also contains playback fields which are ignored. The page and API behavior were observed in a browser, not established as a published stability guarantee.

### Kuwo public playlists (observed 2026-11-16)

Sony Music's [artist-site playlist announcement](https://www.sonymusic.co.jp/artist/nanaoakari/info/559714) links a public Kuwo list at `m.kuwo.cn/newh5app/playlist_detail/{ID}`. This mobile H5 alias carries the same numeric playlist ID as `/playlist_detail/{ID}` and is accepted by the existing Kuwo route parser; the ID is passed to the same public playlist retrieval flow.

The legacy public link `https://www.kuwo.cn/playlist/index?pid=3527541442` redirects in Chrome to `/playlist_detail/3527541442?pid=3527541442`, where the same playlist title and visible tracks appear. GoMusic extracts the exact numeric `pid` and sends it through the same H5 content and metadata retrieval path; it does not need to depend on the browser redirect.

For the linked playlist `3527541442`, the share URL redirected to the canonical `/playlist_detail/3527541442` page, whose browser-rendered view exposed 15 song links. The `newh5/playlist/content?pid=3527541442` page used by GoMusic exposed 16 ordered `li.singBox` rows with stable `mid` IDs, and the existing public `pl.svc` metadata endpoint reported `total=16` while returning an empty `musiclist`. The H5 rows and total therefore agree; the canonical page snapshot is a shorter rendered view, not evidence that the 16-row list should be truncated. A Go-client live fetch could not be completed in the current environment because its DNS resolver could not resolve Kuwo hosts; see `kuwo-official-mobile-share-live.log` and `kuwo-official-mobile-share-browser-observation.md` in the evidence directory.



The legacy `pl.svc` endpoint was also probed with the documented `pcmp4=1`, `vipver=MUSIC_9.1.1.2_BCS2` and `newver=1` fields. For playlist `2267788529` it returned 15 rows with `total=15` despite the H5 page reporting 50; for `236289985` it returned 9 rows with `total=9` despite the H5 page showing 20. On the larger sample, later `pn` values returned no rows. This variant is not used because it would underreport both playlists; see `kuwo-npl-params-probe.log`.

The official [Kuwo H5 playlist page](https://www.kuwo.cn/newh5/playlist/content?pid=236289985) renders the playlist title and ordered `li.singBox` rows, with song title, combined artist text and a `mid` track ID. For this public sample the H5 page showed all 20 tracks. The public [playlist JSON endpoint](https://nplserver.kuwo.cn/pl.svc?encode=utf-8&identity=kuwo&keyset=pl2012&op=getlistinfo&pid=236289985&pn=0&rn=1000&ttime=2006012011) reported `total=20` but returned only four `musiclist` rows in the live browser request. A direct Go-client probe with `rn=4` and `pn=0..5` also returned those same four sparse rows across the pages, with the other pages empty; the interface did not provide the missing sixteen rows.

For the 50-track public playlist `2267788529`, the H5 page initially rendered 30 rows. Clicking the visible “获取更多” control issued `GET /newh5/playlist/playlistByPage?id=2267788529&pn=1&rn=30`, returned HTTP 200 with 20 ordered `li.singBox` rows, and then hid the control. A direct request to the observed next page (`pn=2&rn=30`) returned HTTP 200 with no rows for this sample. The Go adapter now reads only each row's title, artist and `mid`, follows 30-row pages until a short or empty response, and deduplicates by stable ID. The live Go client returned all 50 tracks in order and marked the sample complete. A second public playlist, `3135508477`, returned 162/162 tracks through sequential continuation pages `pn=1` to `pn=5`; the opt-in live test asserts completeness and sequential page numbers. The network capture and parsed response are recorded in `kuwo-h5-continuation-observation.md` and `kuwo-playlistByPage-current.log` in the evidence directory. No hidden external Kuwo script or audio endpoint was inspected.


When that H5 share page is unreadable, GoMusic also requests the public `m.kuwo.cn/newh5app/wapi/api/www/playlist/playListInfo` interface in numbered pages. For the 20-track public sample, its API returned 8 rows and reported 8; it did not expose the other 12 H5 rows. GoMusic uses the returned page order as a best-effort fallback, preserves the larger total from the existing metadata interface, and always marks this fallback partial. The paging parameters were independently checked against live public responses; no site script was inspected.

A separate `www.kuwo.cn/api/www/playlist/playListInfo` route referenced by public clients was probed with `pn=1`, `rn=100` and `httpsStatus=1` for public playlists `2267788529` and `236289985`. Both requests returned HTTP 200 with `success=false` and `message="The request is illegal!"`, without playlist data. GoMusic does not use this route or attempt to obtain hidden request tokens; see `kuwo-www-api-probe.log` in the evidence directory.

The Qishui share-page shape was also verified directly against the issue #20 public example: `_ROUTER_DATA.loaderData.playlist_page`. Current official links include the short `qishui.douyin.com/s/{code}` form and `music.douyin.com/qishui/share/playlist?playlist_id={ID}`; a current [public long-link example](https://music.douyin.com/qishui/share/playlist?auto_play_bgm=1&playlist_id=7203983736064622592) includes tracking parameters. The parser accepts only those observed routes plus the public `/luna/playlist/detail` route used by the primary cursor adapter; extra tracking parameters are ignored. Cursor, response and song limits are enforced by GoMusic.

### Kugou numeric codes

The official `https://t.kugou.com/command/` protocol was researched in [LX Music's implementation](https://github.com/lyswhut/lx-music-desktop/blob/323e4bac505da428adae8db6b58039fb2b36b86d/src/renderer/utils/musicSdk/kg/songList.js) and cross-checked against [wp_MusicApi](https://github.com/GitHub-ZC/wp_MusicApi/blob/bf9307dd138dc8ac6c4f7de29361209d4f5b665f/routes/v1/kugou/playlist.js). Both source snapshots are Apache-2.0 licensed. Only endpoint/request-field protocol facts informed this independently written Go adapter; their JavaScript was not copied or executed.

On 2026-11-15, the provided code `40725013` returned a type-4 playlist with `global_collection_id=collection_3_606105881_4_0` and count 12. The adapter uses that explicit public identity rather than hardcoding a code-to-playlist map or deriving an identity from a user's query parameters. Existing collection/special pagination, total preservation and partial-result reporting still apply. The public fixed command-protocol parameters are not user account credentials. Code parsing accepts bare digits and an optional `酷狗码` / `Kugou code` label, while official URLs retain precedence in share text.

### Observed Kugou GCID mapping

GoMusic independently checked the public pairs `gcid_3z17seve8z2z051` → `collection_3_2248574973_2_0` and `gcid_3zbivkavz4z072` → `collection_3_606105881_4_0`. The known v3 zero-tag shape separates base-35 fields with `z`; its owner and list fields reproduce those IDs. This is an inference verified against these public samples, not a claim that every GCID format is reversible or that the trailer has been authenticated.

The adapter requires the decoded owner to equal the official share-page `list_create_userid` and requires the retrieved collection's entire visible song prefix to match by stable hash before accepting it. The user's original [public share](https://m.kugou.com/songlist/gcid_3zbivkavz4z072/) exposes 10 previews but its validated [public collection](https://activity.kugou.com/share/index.html?global_specialid=collection_3_606105881_4_0) returns 12. This additional path does not require a login or use a third-party hosted service. Failed validation retains the partial-result warning.

MIT sources used for signature/protocol references retain their notices in [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md). The additional Apache-2.0 sources above were consulted for command endpoint and request-field protocol facts without incorporating their code. No changes were made to FluentRead or its reference repositories.

## Frontend choice

[Element Plus](https://element-plus.org/en-US/guide/design.html), [Reka UI](https://reka-ui.com/) and retaining Vue with native controls were compared for this form/preview page. Element Plus was globally loaded in the old application. Reka offers unstyled accessible components but this page needs only ordinary forms, selects, checkboxes and disclosure controls.

The chosen implementation keeps Vue, replaces Vue CLI with [Vite](https://vite.dev/guide/), uses TypeScript and native controls, and removes the global UI library, Axios and the global `ResizeObserver` override. It uses system fonts, same-origin API calls, and no external advertising script. The original GitHub Star badge, migration instructions, support QR and supporter list remain visible.

Actual browser checks cover initial/loading/result/error states, download contents, cancellation/retry, 500-track batches, preferences, and desktop/mobile overflow. Live screenshot inspection additionally reads a real public playlist and verifies that clipboard contents match the export. The final design follows the owner’s review: a white single-column page, black/gray text and a pale-red accent on primary buttons. The source-platform title stays concise as providers expand, with automatic detection shown beside the input. Original-name, format and order controls are visible before fetching; the result area is always present. Help, the original support QR and supporter list are shown without collapsed panels. A retrieved source title uses the generic “Name” label for playlists. Initial input remains empty; example playlist names are never hardcoded into the product UI. The GitHub Star badge and Chinese/English switching are preserved.

## Structure

- `internal/config`: explicit environment configuration.
- `internal/musicurl`: official-host validation, share extraction and provider IDs.
- `logic.Service`: provider adapters and common raw metadata/export contract.
- `repo`: optional raw metadata repositories, with request-scoped deadlines and expiration.
- `handler`: legacy/versioned contracts, input limits, health and static frontend.
- `static/src`: Vue components, fetch/error boundary, export utilities and local formatting.

Legacy cache tables/keys are not rewritten. New raw metadata uses `song_metadata` and `gomusic:v2:` Redis keys. Titles are not unique, and presentation choices never contaminate stored metadata.
